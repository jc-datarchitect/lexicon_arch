# Manual de Onboarding Técnico: Glosario

Bienvenido al equipo. Este documento es tu guía rápida para entender cómo nos comunicamos técnica y operativamente. Nuestro objetivo es que todos hablemos el mismo lenguaje desde el primer día.

## 1. ¿Por qué usamos este glosario?
En arquitectura, las palabras importan. Confundir un *Ramp* con un *Slope*, o no entender la diferencia entre *Construction Documents (CD)* y *Shop Drawings*, puede causar retrasos y errores costosos en obra. 

Este glosario es nuestra **Fuente Única de Verdad (SSOT)**.

## 2. Cómo usar este repositorio
Antes de preguntar a un colega o inventar un término nuevo, sigue estos pasos:

1. **Consulta:** Busca el término en el archivo [data/lexicon_arch.csv](data/lexicon_arch.csv).
2. **Contexto:** Si tienes dudas sobre cuándo usar una palabra frente a otra (ej. *Renovation* vs *Restoration*), consulta [data/lexicon_vs.csv](data/lexicon_vs.csv).
3. **Aplicación:** Utiliza siempre el `acronym_abrev` indicado para tus etiquetas (tags) en BIM, nombres de archivos y reportes.

## 3. Reglas de Oro para la comunicación
* **Consistencia:** Si el glosario dice `CD`, usa `CD`. No inventes `ConstDocs` ni `CDs`. La estandarización facilita la automatización de datos.
* **Bilingüismo:** Trabajamos en un entorno ENG-ESP. Usa siempre el término en inglés para la documentación técnica y el español para la clarificación, tal como aparece en el archivo maestro.
* **Propuestas de mejora:** El léxico evoluciona. Si encuentras un término técnico nuevo o crees que una definición no es clara, no la cambies directamente.
    * *Proceso:* Abre un *Issue* en el repositorio o envía una propuesta al equipo de Data Governance para que sea revisada y validada antes de actualizar el CSV maestro.
